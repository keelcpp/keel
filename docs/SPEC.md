# ТЗ: библиотека keel

keel — публичная лёгкая библиотека на C++20 под лицензией 0BSD. Она дополняет стандартную библиотеку там, где решения std спорны или тяжелы, и прозрачно принимает std-типы на входе.

## Цель и рамки

keel даёт базовые типы, контейнеры, работу с текстом и файлами без тяжёлых заголовков, исключений и скрытых аллокаций std.

- **Аудитория:** все, кому важны время сборки, Debug-производительность и предсказуемость: игры, инструменты, системный и встраиваемый код.
- **Не замена std целиком.** Тяжёлые владеющие контейнеры std (`std::vector`, `std::string`) остаются выбором пользователя; keel принимает их через `Ref`-типы.
- **Вне рамок:** регулярные выражения, локали, календари, сеть, сериализация, обобщённый `variant`, `shared_ptr`.
- **Лицензия:** 0BSD.
- **Стороннего кода нет.** Всё, включая форматирование чисел с плавающей точкой, пишется в проекте.

## Принципы дизайна

1. **Лёгкие заголовки.** Публичные заголовки включают только `<cstdint>`, `<cstddef>`, `<new>` (около 150 строк каждый). Для сравнения, на libstdc++ 13 `<optional>` — около 6 900 строк, `<string_view>` — около 13 800.
2. **Нейтральность к исключениям.** keel сам не бросает и собирается с `-fno-exceptions -fno-rtti`, но остаётся корректным, если исключение бросит пользовательский код.
3. **Явность.** Копирование только через `clone()`, аллокатор передаётся явно, все аллокации видны в коде.
4. **Debug-производительность как требование.** Неглубокие шаблоны, без цепочек базовых классов.
5. **Только UTF-8 в API.** UTF-16 существует лишь внутри платформенного слоя.
6. **Модульность.** Каждый компонент — отдельный заголовок; зависимости только вниз по слоям.
7. **Интероп без включений.** `Ref`-типы принимают любой тип с `data()`/`size()`; типы keel сами отдают `data()`/`size()`/`begin()`/`end()`; конверсии в std-типы — в отдельном `keel/interop_std.h`.
8. **Без глобальных статических конструкторов.**

## Соглашения об именах

keel сознательно не выглядит как std: другой стиль имён сигнализирует о другой семантике.

| Что | Стиль | Пример |
| --- | --- | --- |
| Пространство имён | строчное | `keel::` |
| Типы, шаблоны, концепты | `PascalCase` | `HashMap`, `StringRef`, `Result` |
| Функции и методы | `snake_case` | `path_join`, `read_file` |
| Значения перечислений | `PascalCase` в `enum class` | `ErrorCode::NotFound` |
| Макросы | `UPPER_CASE` с префиксом | `KEEL_ASSERT`, `KEEL_TRY_ASSIGN` |

**Уровни владения и размещения памяти (`*Ref` / `Fixed*` / `Small*` / `<Base>`):**
- `*Ref` — невладеющий взгляд (`StringRef`, `ArrayRef<T>`, `MutArrayRef<T>`, `FunctionRef<Sig>` в `keel/ref.h`). Где возможно, параметры помечаются `KEEL_LIFETIMEBOUND` (`[[clang::lifetimebound]]` / `[[msvc::lifetimebound]]`).
- `Fixed*<N>` — строго фиксированный буфер на стеке без единого обращения к аллокатору (`FixedString<N>`, `FixedArray<T, N>`, `FixedRing<T, N>`, `FixedFunction<Sig, N>`).
- `Small*<N>` — инлайн-буфер на стеке до `N` элементов/байт с автоматическим переходом в `Allocator*` при превышении `N` (`SmallString<N>`, `SmallArray<T, N>`, `SmallRing<T, N>`, `SmallFunction<Sig, N>`). Никогда не хранит указатель внутрь собственного стекового буфера (`is_inline()`).
- Базовое имя без префикса — динамический буфер в `Allocator*` без накладных расходов на SBO (`String`, `Array<T>`, `Ring<T>`, `Function<Sig>`, `HashMap<K, V>`, `HashSet<K>`).

**Глаголы методов:** если смысл операции такой же, как в std, — глагол из std; если другой — другой глагол.

| Операция | Совпадает со std? | Имя |
| --- | --- | --- |
| Размер, данные, обход | да | `size()`, `data()`, `begin()`/`end()` |
| Проверка на пустоту | да | `empty()` с `[[nodiscard]]` |
| Добавить в конец, убрать с конца | да | `push_back`, `pop_back` |
| Ёмкость, размер | да | `reserve`, `resize`, `clear` |
| Удалить по индексу | нет: в std `erase` принимает итератор | `remove_at(i)` |
| Удалить за O(1), переставив последний элемент | в std нет | `swap_remove(i)` |
| Поиск в хеш-таблице | нет: у нас указатель или `nullptr` | `get(key)` |
| Найти или вставить | в std нет | `get_or_insert(key)` |
| Вставка/обновление в хеш-таблице | нет | `put(key, val)` (`true` если ключ новый), `try_insert(key, val)` |

Члены, которых требует язык или экосистема (`begin`, `end`, `data`, `size`), всегда в стандартном виде.

## Модель ошибок

Три вида ошибок обрабатываются по-разному.

| Вид | Пример | Обработка |
| --- | --- | --- |
| Ошибка программиста | выход за границы, нарушение предусловия | `KEEL_ASSERT`, аварийное завершение |
| Ожидаемый сбой | файла нет, строка не число | `Result<T>` или `Error` с `[[nodiscard]]` |
| Нехватка памяти | аллокатор вернул пусто | обработчик `keel::set_oom_handler`, по умолчанию аварийное завершение |

- **Сужение поверхности.** Функции, которые не могут ожидаемо сбоить (`push_back`, `put`, `append`), возвращают `void` (или `bool` для признака перезаписи). `Result` есть только у ввода-вывода, вызовов ОС и парсинга.
- **`Error`** — маленький тип-значение без аллокаций: код из `enum class ErrorCode` плюс системный код ОС (`i32 os_error`). Текст — отдельной функцией `error_message(e)`. API с подробностями (позиция при парсинге) имеют свой тип ошибки, например `ParseError { code, offset }`.
- **Ранний возврат** — переносимые макросы, без statement expressions: `KEEL_TRY(expr)` для `Error` / `Result<T>`, `KEEL_TRY_ASSIGN(x, expr)` для `Result<T>`.
- **Конструкторы никогда не ошибаются.** Всё, что может не получиться, делается фабрикой: `static Result<File> File::open(...)`.
- **Липкая ошибка** для последовательных API (запись, сериализация): объект запоминает первую ошибку, дальнейшие операции пустые, проверка одна — при закрытии.
- **Исключения пользователя.** Внутренности keel на RAII: при раскрутке ресурсы освобождаются, состояние остаётся валидным. Перемещение и деструкторы элементов контейнеров обязаны быть `noexcept`; это проверяется при компиляции. Обработчик нехватки памяти может бросать.
- **Проверка границ** включена по умолчанию во всех сборках; отключается макросом `KEEL_NO_BOUNDS_CHECK` (или `KEEL_DISABLE_ASSERTS`).

## Память, владение, размеры

- **`Allocator`** — интерфейс из указателей на `alloc(ctx, size, align)` / `realloc(ctx, ptr, old_size, new_size, align)` / `free(ctx, ptr, size, align)` и контекста `void* ctx`. Контейнеры хранят `Allocator*` в рантайме, поэтому тип контейнера от аллокатора не зависит. Куча по умолчанию глобальная и переопределяемая.
- **`Arena`** — резерв виртуальной памяти (на 64-битных ОС; линейный чанковый режим на `wasm32` / Emscripten), коммит по мере роста, сброс целиком, временные скоупы (`ArenaTemp`). Scratch-арены на поток (`get_scratch`).
- **`Pool<T>` с генерационными хендлами** заменяет разделяемое владение: «слабая ссылка» — проверка поколения.
- **Только перемещение.** Неявного копирования у владеющих контейнеров нет (включая `ArenaArray<T>`); копия — явный `clone()` (рекурсивно поддерживающий вложенные move-only контейнеры). Исключение — тривиально копируемая стековая строка `FixedString<N>` (Rule of Zero).
- **После перемещения объект гарантированно пуст.**
- **Размеры и индексы:** `usize` (`std::size_t`) для размеров, ёмкостей и индексов с явным сентинелом `kInvalidIndex` (`~usize{0}`), что обеспечивает нулевой интероп со стандартными диапазонами (`data()`/`size()`); `isize` (`std::ptrdiff_t`) для знаковых смещений и разностей.
- **Стабильность указателей** у `Array`, `SmallArray` и `HashMap` не гарантируется; это указано в документации каждого типа.
- **Потокобезопасность:** контейнеры не потокобезопасны; аллокатор по умолчанию потокобезопасен.

## Сборка, платформы, заголовки

| Требование | Значение |
| --- | --- |
| Стандарт | C++20 |
| Платформы | Windows, Linux, macOS, WebAssembly (Emscripten) |
| Компиляторы | MSVC 2022, Clang 16+, GCC 12+ |
| Режимы | с исключениями и RTTI и без них (`-fno-exceptions -fno-rtti`, `/EHs-c- /GR-`) |

| Публичные заголовки | только `<cstdint>`, `<cstddef>`, `<new>` |

## Принятые решения по открытым вопросам

- [x] Репозиторий: `github.com/keelcpp/keel`.
- [x] Форма интерфейса `Allocator`: передача `(size, align)` в `alloc`, `(ptr, old_size, new_size, align)` в `realloc`, `(ptr, size, align)` в `free` (позволяет `Arena` расширять последнюю аллокацию на месте и освобождать память без заголовков метаданных).
- [x] Размер буфера `Function<Sig, N>` по умолчанию: `N = 32` байта (4 указателя на 64-битной платформе).
- [x] Имя макроса отключения проверки границ: `KEEL_NO_BOUNDS_CHECK` (а также `KEEL_DISABLE_ASSERTS` для всех ассертов).
- [x] Имена вставки в `HashMap`: `put(key, val) -> bool` (возвращает `true`, если ключ вставлен впервые, `false`, если перезаписан), `try_insert(key, val) -> InsertResult<V>` (`{ V* value; bool inserted; }`), `get_or_insert(key, default_val) -> V&`.
